# KD6-3.7

> A CLI that decodes what a national ID number secretly encodes — for the many countries whose IDs bake in birth date, sex, and birthplace, it reads them straight out of the number.

## When to use
You have a national identification number, social security number, or ID-card number (`document-id`) from a country whose numbering scheme encodes personal data — much of Europe (Estonia, Belgium, Bulgaria, Denmark, Finland, France, Czechia, and others). KD6-3.7 parses the number to reveal the holder's `dob`, sex (a `physical-description` attribute), and often a birthplace `geolocation`/region and sequence info. Excellent for corroborating or challenging a claimed identity and for confirming that an ID number is internally consistent.

## How to use it (`bestInteractionPattern`: cli)
1. Clone `https://github.com/duk3r4/KD6-3.7` and install Python dependencies via pip.
2. Run with the country code and number, e.g. `python kd6-3.7.py est --nin <number>` (use the flag matching the ID type: national ID / SSN / identity card).
3. Read the decoded fields: day/month/year of birth, sex, birthplace/region, sequence number.
4. Cross-check the decoded `dob`/sex/birthplace against what you otherwise know — a mismatch is a red flag on the ID or the claimed identity.
5. Pivot: confirmed `dob` + birthplace narrow public-record and registry searches sharply.

## Inputs → Outputs
- **In:** `document-id` (a national ID / SSN / ID-card number) + its country
- **Out:** `dob`, sex (`physical-description`), birthplace `geolocation`, sequence/checksum info
- **Empty/negative result looks like:** the country isn't supported, or the number is invalid/inconsistent (bad checksum, impossible date). An invalid decode means the number is malformed or fake — itself a useful finding.

## Gotchas & OpSec
- Only works for countries whose IDs actually encode this data; a random or opaque ID scheme yields nothing.
- The ID number is sensitive PII — handle, store, and dispose of it lawfully; decoding is offline but the input is protected data.
- OpSec: passive/offline — no network calls, nothing reaches anyone.

## Overlaps ("do both")
- Feed the decoded `dob` and birthplace into public-records and registry searches to move from a bare ID number to a person; use official government registries to confirm the identity the number points to.

## Trust & verifiability
`trust: community` — an open-source implementation of documented ID algorithms; the decode is mathematically derived, so verify by checking the number's checksum validity and corroborating the decoded fields against an independent source.
